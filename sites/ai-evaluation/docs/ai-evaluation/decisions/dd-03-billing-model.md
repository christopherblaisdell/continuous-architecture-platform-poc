## Context and Problem Statement

The 208x cost difference between Copilot ($0.48/run) and Roo Code + OpenRouter (~$100/run) is almost entirely attributable to **billing architecture**, not model quality. Both used Claude Opus 4.6 on the same workspace with the same scenarios. The difference is structural: how the platform charges for AI processing fundamentally changes the economics.

This decision has the **single largest impact on monthly operating cost** but has been conflated with toolchain selection. Billing model is an independent architectural concern that constrains but does not determine the toolchain choice.

---

## Billing Model Taxonomy

Four distinct billing architectures exist in the enterprise AI market:

### Model 1: Intent-Based Billing

**How it works:** Charges per **user action** (prompt). The platform absorbs all autonomous agent work — tool calls, file reads, searches, sub-agents, context management, retries — at zero marginal cost.

**Provider:** GitHub Copilot Pro+ ($39/month, 1,500 premium requests included)

**Formula:** `Session Cost = User Prompts x Model Multiplier x $0.04`

**Example:** 4 user prompts on Claude Opus 4.6 (3x multiplier) = 4 x 3 x $0.04 = **$0.48**

**Key characteristic:** Cost is decoupled from how hard the AI works. A 4-prompt session that triggers 50 autonomous tool calls costs the same as a 4-prompt session that triggers 5 tool calls.

---

### Model 2: Token-Based (Pay-As-You-Go)

**How it works:** Charges per **input and output token**. Every token sent to and generated by the model incurs a micro-charge. In agentic workflows, context accumulates with each turn — later turns cost exponentially more than earlier ones because the full conversation history is retransmitted.

**Providers:** OpenRouter, AWS Bedrock (direct), Anthropic API

**Formula:** `Session Cost = Sum over all turns of (Input Tokens x Input Rate + Output Tokens x Output Rate)`

**Example:** A 50-turn agentic session on Claude Opus 4.6 via OpenRouter = **~$100**

**Key characteristic:** Cost is directly proportional to how much context the AI processes. Long sessions with large workspaces are expensive. The "re-transmission tax" means static context (workspace files, prior conversation) is re-billed on every turn.

---

### Model 3: Subscription with Ceiling

**How it works:** Flat monthly fee with usage caps. If the cap is reached, the service either throttles, charges overage, or stops.

**Providers:** Anthropic Max ($100/month Professional, $200/month Team)

**Formula:** `Monthly Cost = Subscription Fee (contains usage allowance)`

**Key characteristic:** Budget-predictable like intent-based, but with a fixed ceiling that may throttle heavy days. Higher per-seat cost than intent-based for architecture workloads.

---

### Model 4: Infrastructure-Amortized

**How it works:** The organization hosts its own AI inference infrastructure (Azure AI Foundry, AWS SageMaker). Cost is compute time + storage + networking — paid regardless of whether the model is used.

**Providers:** Azure AI Foundry (self-hosted), AWS SageMaker, on-premises GPU clusters

**Formula:** `Monthly Cost = Compute Hours x VM Rate + Storage + Networking + Engineering Labor`

**Key characteristic:** Cost floor exists regardless of usage. High setup cost. Makes sense only at very large organizational scale where utilization can be kept high.

## Behavioral Economics of Billing Models

Billing model is not just an economic question — it shapes architect behavior.

### Intent-Based: Exploration Is Free

Under intent-based billing, the marginal cost of the AI doing more work is zero. This creates a positive feedback loop:

- Architect asks a follow-up question: **$0.12** (one prompt x 3x)
- AI investigates 15 files, runs 8 tool calls, produces a detailed analysis: **$0** (autonomous)
- Architect asks for a deeper investigation: **$0.12**
- AI spawns a sub-agent, searches the full workspace, cross-references 5 ADRs: **$0**

**Behavioral outcome:** Architects are incentivized to use AI deeply and frequently. Cost anxiety does not suppress exploration. The AI becomes a true force multiplier because there is no penalty for thoroughness.

### Token-Based: Every Token Has a Price

Under token-based billing, every piece of context has a visible cost. This creates cost anxiety:

- Architect asks a question: **~$0.50** (initial context + prompt)
- AI investigates 15 files: **~$5.00** (context grows, retransmitted)
- Architect asks follow-up: **~$10.00** (full history retransmitted + new context)
- AI does deep analysis: **~$20.00** (context at 100K+ tokens)

**Behavioral outcome:** Architects self-censor. They avoid follow-up questions. They limit context (fewer files loaded). They terminate sessions early rather than exploring. The AI becomes a chatbot rather than an agent because unconstrained agency is too expensive.

### The Self-Censoring Problem

Cost anxiety is not hypothetical. It is documented in the Phase 1 evaluation:

> "Under raw token billing, every additional context file and every follow-up question has a visible cost, which creates friction that reduces AI adoption." — DP-02 analysis

The productivity loss from self-censoring is unmeasurable but real. An architect who does not ask the fifth follow-up question because it would cost another $20 may miss a critical design flaw.

## Evidence from Phase 1

### Actual Billing Data (March 4, 2026)

| Metric | Intent-Based (Copilot) | Token-Based (OpenRouter) |
|--------|:---:|:---:|
| User prompts | 4 | 4 (approx) |
| Autonomous tool calls | 50+ | 50+ |
| Session cost | **$0.48** | **~$100** |
| Cost ratio | 1x | ~208x |
| Monthly (38 runs) | $39 (fixed) | ~$507 (variable) |
| Cost anxiety observed | No | Yes (auto-top-ups triggered) |

### Root Cause of the 208x Difference

The cost gap is caused by two compounding architectural differences:

1. **Billing unit asymmetry**: Intent-based charges per human intent (4 prompts). Token-based charges per token processed (millions across 50 turns). The denominator difference alone accounts for ~50x.

2. **Context management asymmetry**: Copilot indexes the workspace server-side and retrieves relevant snippets. OpenRouter retransmits the full conversation history on every turn. This "re-transmission tax" compounds quadratically with session length, accounting for another ~4x.

Combined: 50x (billing unit) x 4x (context management) = **~200x**, matching the observed 208x.

### The Re-Transmission Tax in Detail

| Turn | Copilot Tokens Billed | OpenRouter Tokens Billed | Cumulative Cost (OpenRouter) |
|------|:---:|:---:|:---:|
| 1 | 0 (indexed) | ~5K | ~$0.50 |
| 10 | 0 | ~50K | ~$5.00 |
| 20 | 0 | ~120K | ~$17.00 |
| 30 | 0 | ~200K | ~$40.00 |
| 40 | 0 | ~280K | ~$70.00 |
| 50 | 0 | ~350K+ | ~$100.00+ |

Copilot bills zero tokens for autonomous turns. OpenRouter bills the full accumulated context on every turn.

## Sensitivity Analysis

### At What Workload Does Each Model Win?

| Monthly Runs | Intent ($39 flat) | Token (~$100/run) | Subscription ($100-200) |
|-------------|:---:|:---:|:---:|
| 1 | $39 | ~$100 | $100-200 |
| 5 | $39 | ~$500 | $100-200 |
| 10 | $39 | ~$1,000 | $100-200 |
| 38 | $39 | ~$3,800 | $100-200 (may throttle) |
| 100 | $39 (may overage) | ~$10,000 | $100-200 (likely throttled) |

**Intent-based wins at every workload level** in absolute cost. The only scenario where token-based is competitive is if runs are extremely short (~2 turns) and infrequent (~1/month) — which is not compatible with architecture workflows.

### Break-Even Analysis

For token-based billing to match intent-based at $39/month:

- At $100/run: 0.39 runs/month — less than one architecture session per month
- At $10/run (hypothetical cheaper model): 3.9 runs/month
- At $1/run (future commodity pricing): 39 runs/month

Token-based billing only becomes competitive if the per-run cost drops by **100x** from current levels. Given that context accumulation is inherent to agentic workflows, this requires a fundamental change in how providers price long-running sessions (e.g., prompt caching becoming standard and free).

## Risk Assessment

### Intent-Based Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| GitHub increases multiplier for Claude Opus | Medium | Medium | Monitor announcements; 0x models (GPT-4.1) available as fallback |
| GitHub eliminates "autonomous work is free" model | Low | High | Maintain awareness of token-based costs as benchmark; evaluate subscription models |
| GitHub caps included requests at a lower level | Low-Medium | Low | Current 1,500/month allows ~125 runs; 38 runs/month is well within |
| Model quality degrades on cheaper Copilot routing | Low | Medium | Quality rubric detects regression; switch to higher multiplier if needed |

### Token-Based Risks

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| Context accumulation makes sessions progressively more expensive | Certain | High | Already observed: $100/run. Context condensing is the only mitigation |
| Rate limiting blocks context condensing | Medium | High | Kong failures research documented this failure mode |
| Self-censoring reduces AI value | High | Medium | Behavioral change is hard to measure but reduces ROI |
| API pricing drops significantly | Medium | Low | Even at 50% reduction, still ~100x more expensive than intent-based |

## Decision Drivers

1. **Total monthly cost**: Intent-based is 13x cheaper monthly ($39 vs $507) and 208x cheaper per run
2. **Cost predictability**: Architecture practice needs budget certainty — intent-based delivers this
3. **Usage behavior**: Intent-based encourages deep AI engagement; token-based creates cost anxiety
4. **Transparency**: Token-based provides exact cost data per request; intent-based is opaque
5. **Vendor dependency**: Intent-based is only available from GitHub — billing model locks to one vendor
6. **Future pricing risk**: Intent-based pricing is not guaranteed to remain; token-based is the market norm

---

## Preliminary Recommendation

!!! tip "Working Recommendation: Intent-Based Billing (GitHub Copilot Pro+)"
    Adopt intent-based billing as the primary economic model. The 208x per-run cost advantage, behavioral benefits (no self-censoring), and budget predictability ($39/month) overwhelm the transparency disadvantage. Monitor GitHub's pricing evolution and maintain token-cost awareness as a fallback benchmark.

### Rationale

- 208x per-run cost advantage is structural, not promotional — it stems from billing unit architecture
- The behavioral benefit (no cost anxiety) is a force multiplier for AI adoption
- Budget predictability enables leadership approval without variable cost justification
- The transparency gap (no per-token data) is the accepted trade-off for 208x savings

### Hedge Strategy

- Track total premium request consumption monthly (GitHub dashboard)
- Run one token-based session per quarter to maintain cost awareness
- Evaluate Anthropic Max ($200/month) as a secondary option if GitHub changes terms
- If GitHub pricing changes materially, re-evaluate with current token rates

---

## Consequences

### If intent-based billing is selected

**Positive:**

- $39/month predictable budget per architect seat
- Architects use AI without cost anxiety — deeper investigations, more follow-ups
- 208x per-run savings fund the entire subscription with a single avoided token-based session
- 1,500 included requests/month covers ~125 architecture runs

**Negative:**

- No per-request cost visibility — cannot optimize token usage
- Locked to GitHub Copilot as the only intent-based provider
- If GitHub changes pricing terms, the practice relies on one vendor's goodwill
- Light months still cost $39 regardless of usage

**Neutral:**

- The transparency disadvantage is real but the cost advantage is so large that optimizing token usage would save pennies
- Token-based providers remain available as fallback if the intent-based model collapses
